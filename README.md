# AI Agent 框架选型助手

给「我该用哪个 agent 框架」这类提问用一个**决策树网页**代替人工来回答疑。
形态接近 [distrochooser](https://distrochooser.de/zh-hans)，但**不做加权打分**：一路 yes/no 问下去，直接给唯一结论，
并把沿途每个选择回显成「为什么推荐这个给你」。

## 用法

双击 `index.html` 即可（单文件、零依赖、断网可用）。可以随手丢 GitHub Pages / Cloudflare Pages 发链接给人。

- 键盘：`1` `2` `3` `4` 选择，`Backspace` 回上一题
- 「全部候选」按钮：不进决策树，直接看任意一个方案的完整说明
- 「厂商事件清单」按钮：按时间列出各家厂商的安全/合规事件，每条都带来源链接（4 组 21 条），末尾附社区讽刺歌词《安全对齐》

## 结构

| 部分 | 位置 | 说明 |
|---|---|---|
| 网页本体 | `index.html` | 单文件、零依赖，页面与数据都在里面 |
| 结论页内容 | `RESULTS`（在 `index.html` 内） | 15 个叶子：做法 / 准备 / 坑 / 链接 / 备选 / 系统提示 |
| 决策树 | `NODES` | 每题 2–4 个选项，`next` 指向另一个题目或叶子 |
| 候选总览 | `CATALOG` | 分组展示，点卡片直接打开对应结论页 |
| 厂商事件清单 | `EVENTS` | 4 组 21 条，按时间排；**每条必须有来源**，`tools/check.mjs` 会校验 |
| 社区讽刺歌词 | `SATIRE` | 《安全对齐》5 段 + 11 条对应说明（3 条带可点来源）。曲源：B 站 BV1bBao6xECA（该页面需验证码，原曲作者未能核实） |
| 自查脚本 | `tools/` | 结构校验、渲染与行为校验、预览生成 |

题目顺序：**基础关 5 题**（API key → 命令行 → 系统 → **隐私红线** → **是否要求开源**）→ **主流程**（写代码 / 通用 / 聊天机器人三条支线）。

## 红线机制（别把它做成装饰品）

基础关最后两题不是在收集偏好，而是**约束**：

- `sets:{privacy:"care"}` / `sets:{opensrc:"require"}` 会被记进 `state`
- 与之冲突的选项带 `blockedBy`，命中时**不会**直接跳结论，而是跳到 `guard` 指定的拦截页
- 拦截页可以「知情接受」（`sets:{ack:"<叶子id>"}`）才放行，放行后结论页会打上「已确认接受代价」
- 结论页永远有一段**「对照你的红线」**，逐条核查开源与数据去向；被拦过的选择也会回显

**不变量（`tools/check.mjs` 里用状态机穷举验证）**：设了红线后，冲突结论在用户确认前一律不可达；
且「在意隐私」时仍有 5 个合规方案可选（别把树拦死）；确认接受后原结论仍可到达。

`META` 是每条结论的档案，决定红线怎么判：

| 字段 | 取值 | 含义 |
|---|---|---|
| `open` | `true` / `false` / `null` / `"disputed"` | 开源 / 闭源 / 不适用 / **开源存疑**（宣称开源但仓库洗过历史、锁 PR 关 Issue，无法比对是否同一份代码） |
| `level` | `low` / `cloud` / `warn` / `na` | 数据自控 / 走云端处理 / **有真实回传或上传事件** / 不适用 |
| `advice` | `"avoid"` | 本身就是劝退页（如中转/代充），不参与红线拦截 |

**`"disputed"` 在「要求开源」这条红线下按「不满足」处理**——只读、不可参与、历史被洗净的「开源」，
审计价值要打折，这是判断开源可信度的关键一条。

## 「为什么推荐这个给你」的三种状态

结论页那段逐条依据（`你在前面选了 X，说明 Y`）来自答题路径，所以必须区分三种进入方式，不能都当有路径处理：

| 进入方式 | `visited` | 渲染 |
|---|---|---|
| 答完决策树 | 有 | 逐条依据 + 完整路径 |
| 从「全部候选」点卡片 | 被清空 | **明说「这一页没有逐题依据」** + 给一个「走一遍决策树」按钮（不能静默少一块） |
| 在结论页点「备选卡片」 | 仍是原路径 | 照常显示，但加一条提示：**这些依据属于原结论，不是当前这一条** |

这三条都有断言守着（`tools/render-check.mjs` 的「逐条依据」段），改渲染逻辑时别把 `noPath` / `isAlt` 两个分支弄丢。

## 事实与讽刺必须分开摆（别破坏这条）

事件清单里有两类内容，混在一起会同时毁掉两边：

| 类型 | 位置 | 规矩 |
|---|---|---|
| 事实条目 | `EVENTS` | **每条必须有来源链接**，`tools/check.mjs` 会拒绝没有来源的条目 |
| 社区讽刺作品 | `SATIRE` | 排在事实条目**之后**；每段歌词必须带 `refs`——把这句话指回上面可查的条目。refs 可以是字符串，也可以是 `{x, s:{t,u}}`（带可点来源） |

两条容易写错、已经踩过的坑：

1. **不要默认「对不上 = 只是讽刺」**。写这首歌时我一开始就把「我融资5个亿」标成「属讽刺表述，不作为事实」——逐句去查之后发现每句都有出处
   （融资那条查到了证券时报：种子轮 1.24 亿美元起，2026-05 H 轮 650 亿美元、投后估值 9650 亿美元）。**核对不出来的句子才标，别拿它当默认。**
2. **批评点是话术与行为的落差，不是规模、估值或起家早晚**。融资多、起家早都不是问题，这类事实只作背景铺垫——
   页面上必须写明这一点（`tools/render-check.mjs` 有断言守着），否则读者会以为本页在拿估值当罪状。

页首那句个人附注（`PERSONAL_NOTE`）同理，它自带「仅代表作者个人观点」的标注。

## 改法

- **加一个结论**：往 `RESULTS` 里加一项，再到 `CATALOG` 里加一张卡（`id` 必须一致）。
- **加一道题**：往 `NODES` 里加一项，把某个选项的 `next` 指过来。
- **选项可带这些可选字段**：
  - `reason`：回显成「你在前面选了 X，说明……」——**必须写成一个判断依据，不能只是复述选项文字**
  - `note`：附在选项下方的小字提醒
  - `sys`：`win` / `mac` / `linux` / `mixed`，命中后结论页会自动追加 `sysNotes` 里对应的那一段
  - `sets`：设置红线状态（`privacy` / `opensrc` / `ack`）
  - `blockedBy` + `guard`：红线冲突时改道去的拦截页
  - `personal`：作者个人附注（`{by, text}`），渲染成虚线框并自动标注「仅代表作者个人观点」。
    文案只在 `PERSONAL_NOTE` 常量里定义一次，Claude 与 GLM 两张卡片都引用它——要改措辞改那一行即可，
    想加给别的卡片就再挂一个 `personal` 字段。
- **加一条结论后**：顺手在 `META` 里补 `open` / `level` / `data`，否则 `tools/check.mjs` 会报错。
- **警告型结论**：结论对象里加 `verdict:"care"`，卡片会变成黄色警告样式（中转 / 代充那条就是这样）。

## 自查（改完必跑）

```sh
node tools/check.mjs         # 语法、引号配平、跳转目标、叶子可达性、目录覆盖、红线不变量
node tools/render-check.mjs  # 真跑一遍渲染：逐叶子、红线拦截行为、逐条依据三种状态
node tools/previews.mjs      # 生成 _preview-*.html，用来直接打开某一屏
```

脚本用 `import.meta.url` 定位仓库根目录，**不含任何本机绝对路径**，clone 下来就能跑（只需 Node）。

`tools/check.mjs` 会拦住最常见的两类错误：**引号把 JS 字符串截断**（中文里用了 ASCII 双引号就会中招，所以正文内层引号一律用 `「」`），
以及**加了结论但没接进树**（叶子不可达）。它还会用状态机穷举验证红线不变量。

`tools/render-check.mjs` 用一个极简 DOM 桩把页面真跑一遍，检查输出里有没有 `undefined`、系统提示有没有注入、
拦截页有没有真的拦人、逐条依据在三种进入方式下是否都在。

## 发布

仓库地址：<https://github.com/bomomoQWQ/How-to-choose-harness>

`index.html` 在根目录，所以直接开 GitHub Pages 就能发链接给朋友：
**Settings → Pages → Source: Deploy from a branch → main / (root)**，
之后访问 `https://bomomoqwq.github.io/How-to-choose-harness/`。

推送（本机 git 的 schannel 后端在这台机器上报 `SEC_E_NO_CREDENTIALS`，指定 openssl 后端即可）：

```sh
git -c http.sslBackend=openssl push -u origin main
```

嫌麻烦可以把后端写进仓库本地配置，之后 `git push` 就行：

```sh
git config http.sslBackend openssl
```
